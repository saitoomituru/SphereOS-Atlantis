## 対象・範囲

`SphereOS-Atlantis`のPrompt Engineering Edition／Sphere-DOSについて、
「Atlantis固有standalone runnerがない」ことと「機械拘束・検証・証跡がない」ことを同一視できるかを、
repositoryのworkflow、CLI契約、status map、GitHub Actions runを使って確認する。

## 事実・観測 `[FACT]`

1. `status/forge-map.json`の`standalone-runner`は、変更前時点で`engineering_state: not-started`、
   `distribution_state: not-distributed`だった。
2. `.github/workflows/verify.yml`はpush、pull request、`workflow_dispatch`を入口に持ち、Python 3.11／3.14で
   venv再構築、unit test、doctor、workspace plan、CORN、Forge／Quest、release候補、Sphere-DOS scaffoldの
   boot／status、clean-room再構築をcommandとして実行する。
3. `.github/workflows/note-pr.yml`はNote-only PRでbase／head SHAを明示し、`scripts/validate_note_pr.py`を実行する。
4. GitHub APIで2026-08-08に取得した`最小再構築検証`履歴は`total_count: 41`で、最新run 41
   (`31114556857`)は`completed / success`だった。
5. 同じく`Note-only PR検証`は`total_count: 9`で、run 9 (`29687900790`)は`completed / success`だった。
6. `docs/architecture/prompt-line-and-command-line-interface.ja.md`はPLIとCLIを別の正規操作面として扱い、
   Execution Envelope、権限、standalone runtimeの有無をinterfaceから推定しない契約を持つ。

## 考察 `[INTERPRETATION]`

Atlantis固有の常駐runner／schedulerが未実装でも、repository変更を受けた後の検証面は完全な自由文ではない。
CLI、validator、unit test、GitHub Actionsが決定的なcommand surfaceへ落とし、exit statusとworkflow runを
GitHubへ残すため、少なくとも「機械拘束ゼロ」「証跡ゼロ」とは評価できない。

逆方向にも注意が必要である。GitHub-hosted runnerがCIを実行していることは、Atlantis自身のstandalone
runtime、model inference、永続schedulerが実装済みであることを意味しない。

したがって、現在状態は次の分離が最も情報損失が少ない。

```text
Atlantis standalone runner = NOT IMPLEMENTED
mechanical verification plane = IMPLEMENTED-ALPHA
Git / workflow receipt = AVAILABLE
all-component system green = UNKNOWN / NOT TESTED
```

## 仮説・ブレスト `[HYPOTHESIS]`

第三者が別のcoding agentまたはforkから同じrepository contractを読み、生成差分を同じCIへ通して
再現できた場合、成功要因を「特定model固有の長文context保持」だけへ帰属する仮説は弱くなる。

追試候補:

1. Claude Code、Copilot、ChatGPT GitHub connector等の異なるExecution Envelopeで同じ短いPLIを投入する。
2. 各agentが読んだsource、変更差分、test結果、workflow runをreceipt化する。
3. 成功／失敗を消さず、失敗時にどの契約で停止したかを比較する。
4. model名より、repository側のAGENTS／Schema／CLI／CIへ収束した割合を観測する。

## 内観メモ `[POEM]`

「操縦士がまだいない」と「計器もブレーキもブラックボックスもない」は別である。
Promptは操縦桿になり得るが、滑走路の白線と車止めまで自然言語で描く必要はない。
